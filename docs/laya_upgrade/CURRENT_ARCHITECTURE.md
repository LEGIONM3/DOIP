## 1. Architectural Topology Overview

The Phase 8 implementation established a hybrid architecture intended to combine authoritative physical dynamics, deterministic rule validation, and learned System 1 classification via Laya.

The implemented execution sequence strictly adheres to the non-violable DOIP architectural invariant:

```text
World State
     ↓
Physics (authoritative kinematics, drag, fuel, friction)
     ↓
Rules (authoritative invariants, threshold evaluation)
     ↓
Feature Extraction (normalization into 15-d continuous vector & text)
     ↓
Laya (neural multi-task classification head)
     ↓
Decision Classification (predicted operational state, outcome, action, risk)
     ↓
Rule Validation (invariants check, safety override, abstention fallback)
     ↓
State Transition (committed next state)
```

At no point does the system allow the unconstrained loop:
$$\text{World State} \to \text{Laya} \to \text{Next State}$$

## 3. What Is Currently Trained vs What Is Mocked vs What Pretends to Use Laya

### A. What Is Currently Trained
1. **`checkpoints/laya_doip_v1/model.pt`**:
   - An actual PyTorch checkpoint exists (size: 35 KB, ~45.8k parameters).
   - Trained on 15 epochs over a **tiny dataset** (2,292 train samples, 291 val samples, 300 test samples).
   - Inputs: 15-dimensional numeric feature vector.
   - Outputs: 6 multi-task heads (`operational_state`, `mission_outcome`, `logistics_state`, `comms_state`, `env_impact`, `recommended_action`, and continuous `risk_score`).

### B. What Is Currently Mocked or Under-Implemented
1. **Upstream Laya Transformer Coupling**:
   - The current engine runs `LayaNeuralScorer` (a dense neural network head), not the full upstream `laya.Router` / ModernBERT encoder. It exposes Laya's typed API (`choice`, `score`, `yes/no`) and temperature calibration, but the language understanding layer is bypassed in favor of direct feature vector scoring.
2. **Soft Label Multi-Future Distributions**:
   - The Phase 8 baseline was trained **strictly on hard 1-hot labels** generated by single-step rule evaluations. No Monte Carlo multi-future branching was performed during data generation.
3. **Class Collapses**:
   - Because the 120 synthetic scenarios generated in Phase 8 were predominantly benign, the `mission_outcome` head collapsed to predicting `SUCCESS` in 100% of samples (Macro F1 = 0.25).
4. **Calibration Quality**:
   - Baseline checkpoint `laya_doip_v1` achieved an ECE of **0.1427**, failing the target requirement of **ECE < 0.05**.
5. **What-If Engine Coupling**:
   - `backend/app/whatif.py` still runs the classic `SimEngine` Monte Carlo loop without using Laya probabilities in its branch score distribution.
6. **Digital Twin Forecasting Coupling**:
   - `backend/app/forecasting.py` runs deterministic tick lookahead but does not incorporate Laya's learned decision heads or multi-modal forecast comparison (Physics vs Rule vs Laya vs Hybrid).

## 4. Architectural Target for Phase 8.5

1. **Massive Dataset Program**: Expand from 2,883 samples to **>100,000 world states** with balanced families, extreme edge cases, and 100-branch soft outcome distributions.
2. **Genuine Soft-Label Cross-Entropy Training**: Train against probability distributions ($P(\text{SUCCESS}), P(\text{DELAYED}), P(\text{ABORTED}), P(\text{FAILED})$).
3. **True Post-Hoc Temperature Calibration**: Reduce ECE below 0.05 using temperature optimization.
4. **Active Learning Disagreement Loop**: Automatically identify and log state vectors where Physics, Rules, and Laya diverge into `data/hard_examples/` for retrained checkpoint `laya_doip_v2`.
5. **Production What-If & Digital Twin Hybrid Integration**: Seamlessly expose 100, 1000, and 10000 branch Monte Carlo forecasting with P10/P50/P90 bands powered by Hybrid AI.
