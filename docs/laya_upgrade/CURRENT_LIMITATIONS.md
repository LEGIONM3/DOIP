## 2. In-Depth Technical Limitations

### 1. Training on Hard Labels Instead of Multi-Future Branching
Ground truth labels were generated by evaluating the rule engine on the current instantaneous state ($S_t$). In reality, military and operational doctrine requires anticipating future branch divergence ($S_{t+k}$). Without multi-future branch rollouts (e.g. 100 branches per state with varied environmental and tactical perturbances), the model learns a rigid mapping rather than a true risk and outcome probability distribution.

### 2. High Expected Calibration Error (ECE)
The current checkpoint achieves an ECE of **0.1427**, which is unacceptable for high-stakes operational planning. Probabilities produced by the softmax layer are overconfident and poorly calibrated. The target specification requires **ECE < 0.05**.

### 3. Disconnection from What-If and Digital Twin Forecasting
The two most critical wargaming subsystems in DOIP—What-If Monte Carlo wargaming and Digital Twin multi-tick forecasting—are decoupled from the Laya engine. When an operator runs a What-If scenario or generates a forecast, Laya's neural predictions are not integrated into the branch risk envelopes, P10/P50/P90 distributions, or turning-point analyses.

### 4. Absence of Active Learning & Disagreement Mining
When the rule engine and Laya disagree, or when Laya's confidence drops below the threshold, the events are not collected, formatted, or persisted. As a result, there is no automatic feedback loop to harvest hard examples and trigger continuous model improvement.

### 5. Single Version in Model Registry
`LayaModelRegistry` only has a hardcoded entry for `laya_doip_v1`. There is no versioning framework supporting comparison between baseline (`laya-base`), operational v1 (`laya-doip-v1`), and fine-tuned v2 with active learning (`laya-doip-v2`).
